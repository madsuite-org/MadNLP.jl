Linear solvers

Direct linear solvers

Each linear solver employed in MadNLP implements the following interface.

MadCore.AbstractLinearSolver — Type
AbstractLinearSolver

Abstract type for linear solver targeting the resolution of the linear system $Ax=b$.

source
MadCore.introduce — Function
introduce(::AbstractLinearSolver)

Print the name of the linear solver.

source
MadCore.factorize! — Function
factorize!(::AbstractLinearSolver)

Factorize the matrix $A$ and updates the factors inside the AbstractLinearSolver instance.

source
MadCore.solve_linear_system! — Function
solve_linear_system!(::AbstractLinearSolver, x::AbstractVector)

Solve the linear system $Ax = b$.

This function assumes the linear system has been factorized previously with factorize!.

source
MadCore.is_inertia — Function
is_inertia(::AbstractLinearSolver)

Return true if the linear solver supports the computation of the inertia of the linear system.

source
MadCore.inertia — Function
inertia(::AbstractLinearSolver)

Return the inertia (num_pos, num_zero, num_neg) of the linear system as a tuple.

Note

The inertia is defined as a tuple $(num_pos, num_zero, num_neg)$, with

  • $num_pos$: number of positive eigenvalues
  • $num_zero$: number of zero eigenvalues
  • $num_neg$: number of negative eigenvalues

Selecting a linear solver

The sparse linear solvers are implemented in package extensions. Each is selected with a marker type, passed as the option linear_solver; the extension is loaded together with the package it wraps (MadNLP loads MUMPS, SuiteSparse, LDLFactorizations and HSL).

MadCore.AbstractLinearSolverMarker — Type
AbstractLinearSolverMarker

Supertype of the names that select a linear solver implemented in a package extension, such as MumpsSolver. A marker is an empty type: passing it as linear_solver selects the solver, and solver_type returns the type that implements it once the extension is loaded.

Calling a marker like a constructor, MumpsSolver(A; opt), builds the solver implemented by the extension.

source
MadCore.solver_type — Function
solver_type(linear_solver::Type)

Return the type implementing linear_solver. By default this is linear_solver itself. A marker such as MumpsSolver is mapped to the type defined by its package extension, and throws an error if that extension is not loaded.

Any type can select a linear solver, so a package that keeps MadCore as a weak dependency can export a plain struct FooSolver end and add, in its extension, MadCore.solver_type(::Type{FooSolver}) = FooState.

source
MadCore.backend_package — Function
backend_package(marker::Type{<:AbstractLinearSolverMarker})

Return the name of the package that loads the extension implementing marker.

source
MadCore.default_sparse_solver — Function
default_sparse_solver(nlp)

Return the sparse linear solver used when the option linear_solver is not set. MadCore and MadNLPCore return DummySolver, which throws an error when the solver is built; MadNLP sets the default to MumpsSolver.

source
MadCore.DummySolver — Type
DummySolver

Default sparse linear solver of MadCore and MadNLPCore, which ship without one. Options and solver setup accept it, but building it throws an error asking for the option linear_solver. MadNLP replaces it with MumpsSolver.

Iterative refinement

MadNLP uses iterative refinement to improve the accuracy of the solution returned by the linear solver.

MadCore.solve_refine! — Function
solve_refine!(x::VT, ::AbstractIterator, b::VT, w::VT) where {VT <: AbstractKKTVector}

Solve the linear system $Ax = b$ using iterative refinement. The object AbstractIterator stores an instance of a AbstractLinearSolver for the backsolve operations.

Notes

This function assumes the matrix stored in the linear solver has been factorized previously.

source
MadCore.AbstractIteratorMarker — Type
AbstractIteratorMarker

Supertype of the names that select an iterative refinement method implemented in a package extension, such as KrylovIterator. Passing a marker as the option iterator selects the method, and iterator_type returns the type that implements it once the extension is loaded.

source
MadCore.iterator_type — Function
iterator_type(iterator::Type)

Return the type implementing iterator. A subtype of AbstractIterator is returned unchanged; a marker such as KrylovIterator is mapped to the type defined by its package extension.

source
MadCore.KrylovIterator — Type
KrylovIterator

Select GMRES iterative refinement of the KKT system, preconditioned by the factorized KKT system. Implemented in the extension loaded by Krylov.
